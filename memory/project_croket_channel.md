**2026-11-03 첫 처리.** 네이버 스마트스토어 말고 **크로켓(Croket)** 이라는 별개 채널로도 판다.
거래 내역은 사장님이 **`<기간> 핀치마트셀러 거래 내역 리스트.xlsx`**(무암호, 네이버와 달리 비번 없음)
로 내려받아 준다.

## 네이버와 다른 점 (혼동 금지)

| | 네이버 | 크로켓 |
|---|---|---|
| 수수료 | 상품가 **6.6%** · 배송비 **3.63%** | **총 거래금액(배송비 포함) 8% + 그 부가세 10%** = 실질 **8.8%** |
| 매출 기준 컬럼 | `정산예정금액`(BD) | `정산 예정 금액 (쿠폰, 광고 차감 전)` |
| 파일 암호 | `1111` | **없음** |
| 통관 | — | 주문마다 **개인통관고유부호** + `통관전용 주문번호` |

검산식: `총 거래금액 × (1 − 0.088) = 정산예정`
> (24,000 + 15,000) × 8% = 3,120, 부가세 312 → 39,000 − 3,432 = **35,568** ✅

🚨 **기준 금액을 확인할 것.** 네이버는 상품가·배송비에 **각각 다른 요율**이지만 크로켓은
**배송비까지 합친 총액에 한 번에 8%**. 2026-11-03 에 `3,120 ÷ 24,000 = 13%` 로 역산해
"상품가 13%" 로 잘못 적었다가 사장님이 보내준 정산 화면의 `플랫폼 이용료(8%)` 표기로 정정했다.
**나눗셈이 깔끔하게 떨어져도 그게 올바른 기준이라는 뜻은 아니다.**

## 정산 파일

**`output/settlement/정산_크로켓_<YYYY-MM>.md`** 로 **채널 분리**한다.
네이버 출고일 정산(`정산_<출고일>.md`)에 섞지 않는다 — 수수료율이 달라 합치면 검산이 깨진다.
영수증은 `pending_receipts.py --mark "<key>" --batch "크로켓-<YYYY-MM>"` 으로 마크.

## ✅ 운영 방식 (2026-11-03 확정) — *"같이 보내 한미로, 정산은 따로"*

- **출고는 네이버 배치에 합류.** `convert.py --croket <크로켓_거래내역.xlsx>` 로 한 파일에 병합.
  상품 매칭은 `product-mapping.xlsx` 의 **`크로켓 상품명`** 열(2026-11-03 신설)로 한다.
  매칭 실패는 `CROKET_UNMAPPED:` 로 보고되니 업로드 전에 반드시 채울 것.
- **정산은 채널 분리.** 네이버 출고일 정산에 섞지 않는다(수수료 기준이 달라 검산이 깨진다).
  한미 오피셜이 통합으로 나오면 **크로켓 건 몫만 떼어** 이 파일에 넣는다.
- 월정산(§20-10)·노션 합산 여부는 아직 미정 — 11월 마감 때 결정.
