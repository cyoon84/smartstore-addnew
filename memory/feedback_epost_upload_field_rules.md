우체국택배 업로드가 반려되는 3대 원인과 대응. 전부 `~/.claude/skills/epost-flow/scripts/convert.py`
에 반영돼 있으므로 **다음 배치부터는 자동 처리**된다.

| 반려 메시지 | 원인 | 함수 |
|---|---|---|
| `(형식 : 02-1234-5678(0212345678) 또는 1588-1234)` | 전화번호에 하이픈 없음 | `phone()` |
| `N행이 5열 ( 010-… ) 은(는) 형식오류 입니다` | 일반전화 칸에 휴대폰 번호 | `landline()` |
| `메시지에 수정해야 할 비정상적인 한글조합 문자가 발견되었습니다` | 배송메시지 이모티콘(`^^`) | `memo()` |

1. **전화번호 하이픈 필수** — 11자리 `010-1234-5678`(3-4-4), 10자리 `010-123-4567`(3-3-4),
   서울 `02-1234-5678`(지역번호 2자리). 원본에 하이픈 있으면 그대로.
2. **일반전화 칸(5열)은 유선/대표번호만** — 네이버 `수취인연락처2` 에 휴대폰이 든 경우가 흔하다
   (고객이 같은 번호를 두 칸에 적음). `010/011/016/017/018/019` 로 시작하면 **빈칸**.
   휴대전화 칸에 `수취인연락처1` 이 이미 들어가 연락처 손실 없음. (우길조 `010-5190-5259` 케이스)
3. **배송메시지는 완성형 한글·영숫자·공백·기본 문장부호만** — 낱자 자모·이모티콘·이모지 제거.
   (김지혜 `…부탁드려요^^` → `^^` 제거)
4. **주소 괄호 미닫힘 자동보정 `addr()`** — 여는 괄호 수 − 닫는 괄호 수만큼 끝에 `)` 보충.
   원본은 그대로 두고 부족분만. 한미 `convert.py` 에도 동일 적용.

**🔑 절대 원칙 — 형식 문제는 출력 `.xls` 를 손으로 고치지 말고 스킬을 고친다.**
손으로 고치면 (a) 스킬로 재생성이 안 되는 파일이 되고 (b) 다음 배치에서 같은 반려가 반복된다.
**행 추가**도 마찬가지 — 손으로 append 하지 말고 **소스 엑셀들을 합쳐 `convert.py` 를 한 번만** 돌린다.

**Why:** 2026-08-31 한국발송 7건에서 반려를 세 번 겪었다. 그 과정에서 출력 xls 를 xlwt 로 직접
뜯어고쳤다가 사장님 지적(*"전에 우체국 송장 업로드 스킬도 만들어놨는데"* / *"check epost-flow"*).
⚠️ 전화번호 하이픈은 **우체국 전용** — 한미 양식은 하이픈 없이 정상 동작하므로 건드리지 않는다.
