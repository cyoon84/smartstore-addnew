**리뷰는 4단계 루프로 관리:** 수집 → 노출 → 악성 대응 → 재구매 유도. 포토·영상 리뷰(UGC)가 신뢰도·전환·체류시간에 특히 효과적이라는 업계 통계가 있음(2026-07-08 openads·실무팩 정독).

**Why:** [[project_daily_smartstore_study]] 저녁 공부 루틴에서 리뷰/셀러답변 주제 학습. 기존 §17-1(체류시간 5요소)에 "실사진 확보"가 갭으로 지적돼 있었는데, 확보된 고객 포토리뷰가 그 실사진 소재의 자연스러운 공급원이 될 수 있음.

**How to apply:**
- SEO 리프레시·상세 갱신할 때 그 상품에 쌓인 포토리뷰가 있으면 실사진 소재로 활용 검토(§17 실사진 갭 보완).
- 악성 리뷰는 즉각 반박·감정적 대응 금지 — 사실관계 확인 → 정중한 해명 답변(셀러 답변은 그 자체로 검색 인덱싱되는 SEO 채널이므로 [[feedback_detail_styled_deco_template]] §17-1 "셀러 답변=SEO채널"과 결합) → 반복되면 네이버 신고.
- **채택 안 함:** 리뷰어 모집 후 결제 유도 → 사후 비용 환급하는 "구매평 체험단" 방식(마이크로 인플루언서 캠페인). 실사용이 아닌 대가성 리뷰라 네이버 어뷰징 정책 회색지대 리스크 + 데이터 진실성 원칙과 결이 다름. 우리는 실제 구매고객에게 톡톡으로 리뷰 요청하는 것만 유지(§17-1 기존 룰).
- **🔑 톡톡 리뷰 요청 타이밍 = "구매 직후"가 아니라 카테고리별 지연 (2026-07-24, getm8.ai·i-boss 정독):** 배송 직후는 아직 안 써봐서 리뷰 내용이 부실함 → **식품·일반 건기식 배송완료 후 1~2일 / 뷰티·스킨케어 1~2회 사용 후 2~3일 / 효과체감형 건기식(콜라겐·관절·유산균) 배송완료 후 30일**. 문구는 "포인트 드립니다"·"지금 바로" 같은 혜택직접언급·긴박감 대신 "이벤트 진행 중입니다" 식 정보안내형이 참여율·심사통과율 둘 다 높음.

**🔑 리뷰 포인트 지급 = 스마트스토어센터 공식 기능, 대가성 체험단 대신 이 경로 (2026-08-05 재조사):** "스마트스토어센터 > 고객혜택관리 > 포인트 지급관리 > 포인트 지급"에서 **실제 구매고객이 남긴 정성 리뷰**에 사후 네이버페이 포인트를 소액 지급할 수 있음(플랫폼 공식 기능, 신뢰도 높음 — CS보상 용도와 같은 화면). "구매 선행 + 대가는 사후·소액"이라 위에서 미채택한 "리뷰어 모집→결제유도→환급" 체험단과는 다른 합법 경로. 톡톡 리뷰 요청(위 타이밍 규칙) 후 실제로 정성 리뷰가 달리면 이 기능으로 소액 포인트를 얹는 걸 제안 대상으로 검토(우리가 아직 활성화 안 함 — 사용자 확인 필요, 자동 실행 아님).

**🔑 셀러 답변 = 별점별 톤 분기 + 매번 다른 표현 (2026-08-05, i-boss 실무 Q&A 교차확인):** 1~2점=진심 사과+구체적 개선의지 / 3점=피드백 감사+보완 약속 / 4~5점=감사 인사+자연스러운 재구매 유도. 기존 "셀러 답변도 SEO 인덱싱 — 복붙 금지, 키워드 2~3회 자연 삽입"(§17-1)과 결합해 **매번 톤은 별점 기준으로 분기하되 표현은 매회 새로 쓴다.**

**🔑 신생 스토어는 리뷰 절대량 경쟁 대신 포토/영상 리뷰 비중 + 낮은 반품률 (2026-08-05):** 여러 소스 교차 확인 — 리뷰 랭킹 반영은 절대 개수가 아니라 **카테고리 내 상대 지수**이고, 포토/동영상 첨부 리뷰에 가중치가 더 붙으며, 반품·교환률은 역신호로 스토어 신뢰도(C-Rank)에 누적 반영됨. 절대 리뷰 수로 경쟁 불가능한 신생 스토어(우리)는 **포토리뷰 유도 + 낮은 반품률 유지**가 상대적으로 승산 있는 레버 — 기존 §9(데이터 진실성, 오배송·컴플레인 방지)·§0-∞(제품명 원본그대로, 오배송 방지) 원칙이 이미 이 레버에 기여 중(방향 재확인, 워크플로 변경 없음).

**🔑 "재방문 유입이 신규 유입보다 약 4배 빠르게 성장" — 재구매 유도 전략의 근거 수치 (2026-10-28 재조사):** bizgo.io 정리([bizgo](https://blog.bizgo.io/trend/naver-plus-store-smartstore-growth/)) — 네이버플러스 스토어 D.I.A.+ 랭킹 5대지수(적합도·상품인기도·판매자신뢰도·개인선호도) 중 "개인선호도"는 구매 이력 기반이라 재방문 고객 유입이 신규 유입보다 훨씬 빠르게 성장한다는 수치. 기존 "단골 확보 4가지 전략"(정확한 주문·배송 안내/유용한 소식 전달/재구매 시점 맞춤 안내/구매 후 만족도 관리)과 위 리뷰 유도·톡톡 타이밍 전략이 같은 방향 — 신규 액션 추가 없이 기존 재구매 유도 우선순위를 뒷받침하는 근거로 기록.

**🔑 리뷰 요청 문구 = "칭찬해주세요" 대신 구체적 질문 항목으로 (2026-11-01 재조사):** kimjaeseok.com·getm8.ai 교차확인 — 칭찬을 직접 요청하면 리뷰가 획일적으로 납작해진다. 톡톡 리뷰 요청 메시지에 **사이즈감·포장상태·사용장소 같은 구체 질문 항목**을 제시하면 더 길고 정보성 있는(=포토리뷰 유도에도 유리한) 리뷰가 나온다는 지적. 기존 타이밍 규칙(식품 1~2일/뷰티 2~3일/효과체감형 30일)에 **문구 내용**을 보강하는 것이지 타이밍 규칙 자체는 안 바뀜. 리뷰 이벤트(혜택 걸기)를 할 경우 "리뷰 쓰면 자동 응모" 구조(별도 신청 없이 리뷰 작성 자체가 참여)가 참여율이 높다는 것도 같은 소스에서 확인 — 우리는 리뷰 이벤트를 아직 운영 안 함, Slack 제안으로만 기록.

**🔑 혜택 걸고 리뷰 유도 시 조건 공개는 "권장"이 아니라 공정위 지침 근거가 있음 (2026-11-01, kimjaeseok.com→1차 소스 교차확인):** 공정거래위원회 **「추천·보증 등에 관한 표시·광고 심사지침」(예규 제499호, 2026-06-01 시행)**이 경제적 이해관계(혜택) 공개 원칙의 근거. 이 개정의 신규 조항 자체는 **AI 생성 가상인물이 추천·보증할 때 "가상인물 포함" 표시 의무**(우리는 AI 가상인물을 광고·리뷰에 안 씀 — 직접 해당 없음, 참고 기록만)이지만, 혜택을 걸고 리뷰/추천을 받을 때 그 대가 관계를 공개해야 한다는 기존 원칙은 이 지침 계열이 계속 유지. 우리는 애초에 대가성 리뷰를 안 받으므로(위 "더 보수적으로 간다" 결정) 이 규제가 추가로 바꾸는 건 없음 — 혹시 §네스프레소/§리뷰포인트 지급 기능(미활성)을 나중에 켤 때는 "조건 공지 필수"를 지킬 것.

**🔑 불만/악성 리뷰 답변은 AI 초안에 의존하지 말 것 — "무슨 일이 있었고 무엇을 바꿀지"는 판매자만 안다 (2026-11-01):** 같은 소스 지적 — 칭찬 리뷰 답글은 AI 다듬기로 보조해도 되지만, 불만·악성 리뷰는 **그 사정을 아는 판매자가 처음부터 직접 써야** 한다(AI가 쓰면 사과만 있고 "무슨 일이 있었는지·무엇을 바꿀지"가 빠짐). 기존 §24h(24시간 SLA + 답변 개인화 + 매회 다른 표현) 규칙의 근거를 보강하는 확인 — 워크플로 변경 없음.

**🔑 "합법 체험단"도 있지만 우리는 그보다 더 보수적으로 간다 (2026-10-23 재조사):** 업계 기준상 체험단이 합법이려면 ①실구매 선행 ②대가(협찬) 명시적 공개, 둘 다 충족해야 함. 우리 미채택 결정은 "회색지대라 피함"이 아니라 **합법 기준조차 안 쓰고 더 안전하게(대가 없는 실구매고객 요청만) 간다**는 뜻으로 재확인. 같은 조사에서 국내 이커머스 전반(네이버 포함) AI 허위리뷰 탐지 강화 흐름 확인 — 단속이 느슨해질 방향 아님, 기존 결정 유지.

**🔑 악성 리뷰 24시간 SLA + 월 1회 반복불만→상세반영 + 답변 개인화 보강 (2026-08-16, 실무팩 재정독):** 악성 리뷰는 "정중한 해명 답변"에서 한발 더 — **발생 인지 후 24시간 내 응대**(지연 시 신규 방문자 이탈 유발이 근거). 추가로 **월 1회 그 상품 리뷰를 훑어 반복되는 불만(배송 느림·사이즈 작음 등)을 상세페이지 문구·배송 안내에 직접 반영**하는 루프 — SEO 리프레시(§13)와는 별개 트리거, 리뷰가 상품개선 신호가 되는 구조. 셀러 답변은 **상품명을 구체적으로 언급 + 감사 표현을 매회 다른 문장으로**(동일 문구 반복은 "기계적 인상"이라 역효과 — 위 "매번 다른 표현" 규칙의 구체화). **채택 보류(Slack 제안만):** "포토리뷰 작성자 DB 구축 → 신상품 안내 발송"은 CRM/이메일 인프라 필요, 지금 워크플로엔 안 맞음. (참고: 같은 검색에서 확인한 네이버 공식 보도자료의 "3점 미만 별점 제한·평균별점 공개"(2026-07-09 시행)는 **플레이스(지도) 리뷰 전용**, 스마트스토어 쇼핑 리뷰엔 미적용 — 무관 확인.)
