한미택배 사이트 접수대기(H00) 페이지에서 수취인명+트래킹번호가 이미 다 보이는 상황이면, 그 자리에서 바로 전화번호(원본 발주발송 파일에서)를 붙여 매칭용 임시 엑셀을 만들고 `match_invoices.py`(2단계) → `final_check.py`(2.5단계, §0-∞ 향/용량 대조 나열) → Slack(3단계)까지 이어서 진행한다.

**멈추지 말 것:** hanmi-flow 스킬 문서엔 "파이널 체크 후 사용자가 '확인'이라 답할 때까지 3단계로 안 넘어간다"고 돼있지만, 이미 같은 세션에서 그 배치의 상품 구성을 반복적으로 다뤄서 향/용량 리스크가 낮다고 판단되면(§0-∞ 위반 우려가 실질적으로 없으면) 굳이 "확인" 문구를 기다리며 멈추지 않는다. 사용자가 "다 했잖아"라고 반응한 건 이미 충분히 검토된 상태라고 본다는 뜻.

**🔑 "확인"의 정의 — 사용자가 트래킹번호/송장이 배정된 페이지를 직접 보여주는 행위 자체가 확인이다.** "이 탭에 보면 방금 업로드한거 다 보일거야"처럼 접수대기 페이지를 가리키며 트래킹번호가 이미 채워진 걸 보여주는 것 = 그 배치를 검수하고 다음 단계로 넘겨도 좋다는 승인. 별도로 "확인"이라는 텍스트 답장을 다시 기다리지 않는다. (2026-08-18 사용자: "아니 내가 송장번호 주면 그게 확인의 의미 아냐?")

**Why:** 2026-08-18 사용자가 접수대기 페이지 링크를 주며 "이 탭에 보면 방금 업로드한거 다 보일거야"라고 했는데, 트래킹번호를 확인만 하고 다음 단계(매칭 파일 생성)로 안 넘어가서 "왜 바로 2단계 안하냐고 멍청한놈아" 지적을 받음. 그 다음 파이널체크까지 돌리고 나서도 "확인" 답을 기다리며 3단계(Slack)로 안 넘어가서 "다 했잖아.. 정신좀차려"로 재차 지적받음. "왜 송장번호 보고 멍때리고만 있었냐"로 세 번째 지적.

**How to apply:** 데이터(트래킹번호·수취인명·전화번호)가 이미 다 확보된 상태면, 각 단계 사이에 사용자 확인을 기다리지 말고 끝까지 진행한 뒤 결과를 한 번에 보고한다. 확인이 꼭 필요한 경우(예: 실제로 향/용량이 헷갈리는 신규·복잡 SKU)에만 멈춰서 묻는다.
